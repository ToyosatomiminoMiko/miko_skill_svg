# 踩过的坑

从两个项目(myama 的位图拟合管线、miko_svg_editor 的页面编辑器)里提炼的教训,画新图时
先扫一眼,能省一轮返工。

## 数字与确定性

- **不要 `toFixed`**:它对负数、进位、末位 0 的处理因语言/实现而异,同一数值在不同
  路径下会出现两种文本表示。统一用 `round + 去尾随 0 + 整数不带点`(见 `svgkit.serialize.fmt`)。
- **`str(float)` 会出科学计数法**(`1e-05`)和浮点尾噪声;SVG 虽然接受,但 diff 全是噪声。
- **`-0` 要归一**:`fmt` 里 `round(-1e-9, 4) == 0`,统一输出 `0`。
- **不要在输出里写时间戳、随机 id**:每次生成都不同,就没法用 diff/sha256 判断“几何有没有变”。
- 生成物重复生成必须逐字节一致,这是“能进版本库”的前提。

## 结构

- **mask / 复合 path 是编辑性杀手**:用 `<mask>` 做几何切割,Inkscape 里双击进去只看到
  一个整块,改缺口边界无从下手。能拆成简单多边形就拆。
- **圆角矩形别采样**:`<rect rx>` 让渲染器算圆弧,采样成多边形后放大就有折角。
- **圆别用两段弧拼**:`<circle>` 一行解决,否则改半径要改两处。
- **描边接缝**:`stroke-linecap="round"` 的圆头会露在图形尖端外面,把端点角往图形内部
  多转几度埋进去(参考花环的芒)。
- **变换顺序**:`transform="translate(...) scale(...)"` 从右往左作用;先缩放后平移,
  组内坐标是按缩放前写的,别反过来。
- **半像素约定**:从位图量参数时,numpy“像素索引 = 中心”和 SVG“像素中心 = i+0.5”
  差半个像素;不同部件可能用不同约定,拼装时按部件修正(见 myanmar 例子的
  `PART_PIXEL_OFFSETS`)。

## 自检与回流

- **打开时用的校验器和导出时用的必须是同一个**:编辑器里能打开、导出却生成非法文件,
  通常是两条校验路径漂移了。生成/导出共用一套 `validate`。
- **手改结果不能悄悄覆盖生成结果**:如果允许用户手改 SVG,必须显式走“读回手改文件 →
  重新进入拼装管线”的流程,并在输出里标明用了手改;不要“文件存在就优先用它”当隐藏默认。
- **预览与导出用同一套布局代码**:两套坐标/字号逻辑迟早对不上。
- **分辨率是天花板**:从 800px 位图拟合出来的参数,放大到 4000px 依然是 800px 的细节量。
  别为“放大后更清晰”反复调参,收益递减;要更清晰只能换参考源。

## 字体与文本

- **字体没就绪就量宽会量错**:浏览器环境要等 `document.fonts.ready`;否则回退字体度量
  与最终字体不同,文字位置全错。
- **子集化/嵌入要连许可一起考虑**:字体文件能嵌入不等于允许嵌入;输出要给用户提示。
- **`<text>` 不做自动换行/居中**:多行就多个 `<text>`,或者接受渲染器自己换行。

## 安全与合法性

- 禁止 `<script>`、`<foreignObject>`、`on*` 事件属性、`javascript:` URL;
- 属性值里的 `& < > "` 必须转义;文本节点里的 `& < >` 同样;
- XML 1.0 不允许的控制字符(U+0000–U+001F 里除 `\t \n \r` 的)会让文件直接非法,
  遇到就报错,别悄悄输出;
- 外部引用(`http(s)://` 图片/字体/CSS)在离线环境会丢,生成物必须自包含。

## 画法本身

- **一条 path 画到底**是最大的坑:能选中、能改参数、能看出“这是齿轮”的 SVG,
  比“渲染出来一样”的 SVG 有价值得多;
- 同色图形叠加取并集,不需要布尔运算;异色接缝才需要考虑叠放顺序;
- 轮廓类图形别追位图碎细节,亚像素噪声在目标尺寸下不可见,只会让文件变大、点更难改。
