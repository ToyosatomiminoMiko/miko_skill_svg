# 只有拿到参考位图时才用的参数拟合

**默认不做拟合。** 本技能的正常流程是“人给出几何参数 → 生成 SVG”。只有同时满足
下面两条时才走拟合:

1. 手上有参考位图(或参考 SVG/更高清的原稿);
2. 位图里的形状确实是几何图形(齿轮/星形/圆弧/多边形),不是照片或手绘。

没有参考图就没有目标函数,拟合只会得到“看起来差不多”的随机参数,不划算。

## 流程(与 myama 冻结前的一致)

```
参考位图 ──> 渲染候选 SVG ──> 软覆盖光栅 ──> 指标(MSE / IoU / 双向亚像素边缘距离)
     ^                                              │
     └──────── 分阶段 Nelder-Mead 调参 <────────────┘
```

要点:

1. **先定结构,再拟合数值**:先手工/按几何关系确定“由哪些图元组成、哪些参数可调”,
   拟合只调数值(半径、角度、间距、偏移)。结构错了,拟合救不回来。
2. **分阶段、分部件拟合**:花环、齿轮、结、轮廓各拟各的,最后只调部件间偏移;
   一次全参拟合维度太高,容易卡在局部极值。
3. **软目标优化,硬目标验收**:优化用像素级软覆盖 MSE(可微、平滑);验收用
   IoU + 双向边缘距离(对最终观感更诚实)。只看 MSE 会把参数带偏。
4. **有理有据地停**:分辨率是上限,指标进入平台期就停;继续调是过拟合到压缩噪声。
5. **参数进常量文件,产物进版本库**:拟合结果写回 `constants.py`(唯一调参入口),
   重新拼装后 sha256 应稳定;手动改过的部件要单独标出来,不要混进拟合参数。
6. **手改回流必须显式**:如果某个部件是人工在编辑器里改的,拼装时要显式读取并标注;
   不要“文件存在就优先”这种隐藏默认。

## 什么时候该停下来人工改

- 拟合指标进入平台但某处边缘仍差 1–2px:继续拟合收益递减,人工改轮廓点更快;
- 位图本身模糊/压缩噪点重:目标是“人眼看起来对”,不是“逐像素相等”;
- 形状本来就不是几何图形(手绘曲线、文字):直接人工描,别拟合。

## 内置工具: `scripts/fit.py`(只跑一轮,只给证据)

它是上面流程里最靠前的一步:**把位图变成“顶点证据”**,不做迭代调参、不做渲染比对、
不生成 SVG。依赖 Pillow + numpy(不是标准库,属于“已有依赖”)。

```sh
python3 scripts/fit.py ref.png ref.json      # 也接受只给图片,直接打印
```

一轮做的事:

1. `foreground()`:亮度 ≥ `min_luma` 或彩度 ≥ `sat` 的像素算前景(背景渐变/纯色靠
   亮度上限与低饱和排除);默认 `min_luma=72, sat=28`,背景很亮时调高阈值;
2. `components()`:4 邻接连通域(**不要用 8 邻接**,对角相邻的两块会被粘成一块);
3. `trace()`:Moore 邻域径向扫描描外轮廓(得到闭合像素链);
4. `rdp()`:Ramer-Douglas-Peucker 简化,`eps≈1.6`;45°/90° 边会收敛成一条线段,
   抗锯齿造成的阶梯被吃掉,顶点误差约 1px;
5. 按面积过滤(默认 `min_area=400`),文字/噪点自然消失。

输出 JSON 每块:`color`(像素均值)、`area`(像素面积)、`area_poly`、`bbox`、`centroid`、
`polygon`(简化后的顶点列)。**顶点列不是最终坐标**,只是量参数的起点。

## 拿到 JSON 之后:怎么变成参数

1. **逐行/逐列扫描比顶点更准**:对每个色块取每行的 `min_x / max_x`,45° 边会表现为
   “每行 ±1”,竖直边表现为“常数”。用这些常数反解出图元参数(矩形边界、45° 直线的
   截距、端面位置),比直接用 RDP 顶点稳(顶点会被单像素噪点带偏);
2. **归到一套网格**:同一张图里反复出现的比例(半宽、45° 截距、半径)应当能用少数几个
   常数统一解释;解释不了的地方先怀疑自己量错了,而不是给每块塞独立参数;
3. **对称性由公式保证**:量一个,其余用旋转/镜像生成(见 `examples/ogas_logo/`)。
   不要逐块量、逐块写——那样改一个数就要改八处;
4. **写回 `constants.py`**,绘制代码只读常量。

## 验收(可选,别变成调参循环)

允许做的一次性数值自检:把生成的多边形**自己**光栅化(扫描线 even-odd),和位图色块比
IoU。经验值:逐块 IoU ≥ 0.90 说明形状与位置都对;0.7~0.9 通常是整体平移几个像素,
不是形状错(参考图本身可能不是严格对称的);低于 0.7 才回去查结构。

这一步**只跑一次**,用来抓“方向反了/镜像错了/端点算错”这类硬错误,不是用来迭代逼近。
不要为了把 IoU 从 0.95 提到 0.97 去改参数——那是过拟合到抗锯齿和压缩噪声。

## 边界

- 拟合代码只在本技能里做“一轮证据提取”;**没有**渲染器、没有像素级软覆盖优化、
  没有分阶段 Nelder-Mead。需要那种精度时,去冻结的 myama 仓库取
  `miko_wiki_resource/fitting/` 的现成实现(已停止演进),结果仍只回写 `constants.py`。
- 结构错了拟合救不回来:先定“由哪些图元组成、哪些参数可调”,再动数值。
- 位图本身是手绘曲线/文字/照片时,直接人工描,别拟合。
